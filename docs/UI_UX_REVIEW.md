# UI/UX와 기억·목표·작업 연결 검토

검토일: 2026-09-05. Orca의 실제 서버 화면에서 발견한 문제를 현재 저장소에서 수정했다. 수정 후에는 별도 로컬 서버와 테스트용 PostgreSQL에서 저장·조회하고, Orca에서 데스크톱과 393px 모바일 화면을 조작했다. 운영 서버에는 아직 반영하지 않았다.

## 화면에서 확인한 문제와 수정

| 문제 | 수정한 동작 |
| --- | --- |
| 로그인 전 작업 화면과 인증 오류가 함께 보임 | 인증 상태를 먼저 확인하고 로그인 화면을 표시한다. 로그인 후 이전 화면 주소로 돌아온다. |
| 긴 계정 표시와 반복 요약이 내용을 밀어냄 | 계정 메뉴를 접고, 작업 공간 선택을 사이드바로 옮겼다. 중복 요약·비율·설명을 줄였다. |
| 지도가 첫 화면을 차지하고 항목을 읽기 어려움 | 목록을 기본으로 표시한다. 목록·지도 전환과 항목 유형별 선택을 분리했다. |
| 모바일 메뉴가 잘림 | 화면 선택 상자를 제공하고 목록·상세·필터 배치를 좁은 화면에 맞췄다. |
| 선택 상세를 찾기 어렵고 키보드 이동이 끊김 | 상세로 초점을 옮기고, 닫을 때 선택 버튼으로 돌아온다. Esc로 닫을 수 있다. |
| 빈 보드 칸이 반복됨 | 항목이 있는 상태를 표시한다. 작업이 없을 때는 빈 목록 안내 하나를 표시한다. |
| 사실·가설 메뉴만 있어 경험과 실패 기록을 찾기 어려움 | 기억 메뉴에서 네 가지 유형을 함께 조회하고 유형·내용으로 검색한다. 개요에는 ‘연결된 기억’이라고 표시한다. |
| 기억 내용이 256자에서 끊김 | 상세에서 원문 전체를 나누어 읽는다. 실패의 이유·교훈과 가설의 확인 방법도 조회한다. |
| 큰 프로젝트가 빈 화면처럼 표시됨 | 지도 응답을 크기 제한 안에서 나누어 읽는다. 조회 실패와 실제 빈 목록을 구별한다. |
| 공간을 빠르게 바꾸면 이전 결과가 덮어씀 | 현재 요청의 결과만 화면에 반영한다. 뒤로 가기와 선택 항목 주소도 복원한다. |
| 관리 메뉴가 안내만 표시함 | 에이전트 규칙 복사와 검색 데이터 관리의 조회·다시 시도·다시 만들기를 기존 기능에 연결했다. |
| 상단의 테마 선택이 무엇을 바꾸는지 불분명함 | 사이드바 아래에 ‘화면 모드’라는 이름을 붙이고 기기 설정·라이트 모드·다크 모드를 표시한다. 언어 선택도 함께 배치했다. |
| 화면 문구가 한국어에 고정됨 | 메뉴·상세·오류·처리 결과·에이전트 규칙을 한국어와 영어로 분리했다. 언어를 바꿔도 현재 선택과 원문을 유지한다. |
| ‘작업 연결’이 화면의 의미를 잘 전달하지 못함 | ‘작업 흐름’으로 바꿨다. |

View는 배치·입력·초점 이동을 담당하고, ViewModel은 상태·조회·선택을 담당한다. 문구는 별도 번역 파일에서 관리한다. 기존 API·주소·지도 배치 코드를 재사용했다. 새 라이브러리는 추가하지 않았다.

## 백엔드에서 자동으로 처리하는 부분

- **작업 결과 기록:** 기존 완료·인계·연결 만료 시 경험을 남기는 흐름을 유지한다. 완료 요청을 다시 보내도 같은 결과가 중복 기록되지 않는지 확인했다.
- **사실의 출처:** `fact_sources`에 있는 사실→원본 경험 관계를 작업 지도와 작업 재개 정보까지 이어 준다. 이전에 저장한 사실에도 적용된다. 티켓·목표가 없는 사실도 상세에서 원본 경험을 열 수 있다.
- **직접 지정한 연결 유지:** 에이전트가 직접 연결한 기록을 우선한다. 자동으로 계산한 연결은 별도로 표시하며, 다른 티켓의 기억을 프로젝트 전체에 복사하지 않는다. 만료된 사실은 작업 재개 정보에서 제외한다.
- **작업 묶음의 진행 상황:** 하위 세부 작업에서 완료 수와 표시 상태를 계산한다. 세부 작업이 끝났는데 묶음은 ‘준비’로 남는 표시 문제를 해결했다. 이후 작업이 추가되면 진행 중으로 다시 표시한다. 취소한 작업과 실행할 세부 작업이 없는 묶음도 구별한다.
- **목표 처리:** 세부 작업의 확인 조건과 근거를 검사한 뒤 목표 완료로 이어지는 기존 흐름을 유지한다. 표시용 진행 상태를 계산하면서 저장된 목표 상태나 사용자가 남긴 설명을 덮어쓰지 않는다.
- **큰 응답:** 지도와 기억 원문은 이어 읽을 수 있다. 읽는 도중 내용이 바뀌면 서로 다른 시점의 내용을 합치지 않도록 다시 조회한다.
- **검색 준비와 원문 조회 분리:** 검색용 데이터가 아직 없거나 생성에 실패해도 저장된 원문은 조회할 수 있다. 실제 HTTP 확인에서 발견한 경험·사실 조회 오류를 수정했다.
- **기억 정리 상태:** 남은 처리 분량을 계산하는 SQL에 작업 공간 인수가 빠진 오류를 수정했다.

## 티켓과 역할을 다루는 기준

1. 티켓 없이 작업 공간에 기억만 저장하거나 독립 목표와 기억을 연결할 수 있다. 조회 때문에 티켓을 자동 생성하지 않는다.
2. 같은 프로젝트 안에서도 티켓의 담당·작업 설명·필요한 작업 능력·연결 기억을 각각 유지한다. 구현 티켓과 검토 티켓의 재개 정보가 섞이지 않는지 확인했다.
3. 자동 연결은 저장된 출처와 명시된 관계에 근거한다. 프로젝트가 같다는 이유만으로 담당 역할이나 연결을 추측하지 않는다.
4. 작업 능력 표시는 작업을 배정하기 위한 정보다. 접근 권한을 부여하는 설정으로 바꾸지 않았다. 다른 작업 공간의 원문과 출처 조회는 거부한다.
5. 공통 목표를 지정한 프로젝트의 작업 목표 연결 규칙은 유지한다. 공통 목표를 선택하지 않아도 독립 목표들을 개요에서 볼 수 있다.

## 발전시킬 만한 부분과 남은 한계

- **다음 행동과 근거를 더 가까이 표시:** 작업 상세에서 다음 할 일과 관련된 결정·제약·실패 경험을 우선 보여줄 수 있다. 추천 순서는 실제 참조 기록이 쌓인 뒤 조정하는 것이 좋다.
- **확인이 필요한 항목에서 바로 행동:** 오래된 계획 검토, 확인 전 가설, 목표와 작업 상태의 불일치를 모으되 각 항목으로 바로 이동할 수 있게 한다.
- **큰 공간의 조회 비용:** 현재 지도는 페이지마다 전체 조회 결과를 만들고 변경 여부를 비교한다. 처리 시간이 실제로 길어지면 서버에서 일정 시점의 조회 결과를 유지하는 방식을 검토한다. 항목 한 개도 담지 못할 만큼 응답 제한이 작은 경우에는 원인을 표시한다.
- **작업 흐름 화면의 범위:** 작업 흐름 화면은 최대 200개 작업·400개 관계를 조회하고 더 있으면 일부 표시임을 알린다. 큰 공간에서는 전체 항목을 읽는 개요 목록을 사용할 수 있다.
- **로그인 유지 시간:** 실제 서버에서 세션 만료는 관찰했지만 운영 로그인 제공자의 설정은 확인하지 않았다. 로그인 후 이전 주소 복귀는 구현했으며, 운영 세션 갱신과 유지 시간은 별도 확인이 필요하다.

새 출처 조회용 DB 뷰는 마이그레이션 `00039_work_memory_context.sql`에 포함된다. 운영 반영 시 새 Go 서버 빌드와 해당 마이그레이션 적용이 필요하다.
